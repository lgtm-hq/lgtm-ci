# Migrating from v0.75.x to v0.76.0

v0.76.0 ships the changes merged after v0.75.3: PRs #1089 through #1126
(the external-consumer canary, #1124, merged last) and the Renovate bumps
in PRs #1069, #1070 and #1115 through #1117. Most are bug fixes, but several
change what a caller must grant, pass or commit. This guide lists every
caller-visible change, who it affects, what
breaks if you ignore it, and the edit to make.

Callers pin reusables and composites by SHA, so nothing changes until you move
the pin. Work through the [checklist](#checklist) before or together with the
pin bump.

## 1. Grant `actions: read` to the language test reusables

Source: #1105 (#803).

**Who:** every caller of `reusable-test-python.yml`, `reusable-test-node.yml`,
`reusable-rust-test.yml` and `reusable-test-shell.yml`. No other reusable's
permission union changed in v0.76.0.

**Why:** the aggregate job now waits for the matrix's result artifacts to
appear in the run's artifact listing before it aggregates them (a bounded
wait, 90 s budget). Reading that listing with `GITHUB_TOKEN` needs
`actions: read`. GitHub validates a reusable workflow's permission request
statically, before any `if:` is evaluated.

**Symptom if ignored:** the whole caller run fails at startup
(`startup_failure`): the nested aggregate job requests `actions: read`, which
the calling job did not grant. No job starts, including jobs
unrelated to the test call.

**Change:**

```yaml
jobs:
  test:
    permissions:
      actions: read # new in v0.76.0
      contents: read
      pull-requests: write
    uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-test-python.yml@<sha> # v0.76.0
    with:
      python-versions: "3.12,3.13"
```

The same block applies to `reusable-test-node.yml`, `reusable-rust-test.yml`
and `reusable-test-shell.yml`. Print any workflow's exact union with
`python3 scripts/ci/docs/validate-caller-permissions.py --union <file>.yml`.

## 2. Node runners: `package-manager`, devDependencies, Node 22

Source: #1102 (#1077). Contract:
[Node package-manager contract](../workflow-contract.md#node-package-manager-contract-1077).

**Who:**

- Direct users of the `run-vitest`, `run-playwright` and `run-lighthouse`
  composites.
- Callers of `reusable-test-e2e.yml` / `reusable-test-e2e-matrix.yml` whose
  project uses Bun but who did not pass `package-manager`.
- Any Node project that relied on lgtm-ci installing vitest, the coverage
  provider, `@playwright/test` or `@lhci/cli` for it.
- pnpm projects without a `packageManager` field in `package.json`.
- Anyone relying on the old Node 20 default.

**What changed:**

- `package-manager` (`bun`, `npm` or `pnpm`) is **required** on the three
  composites. It is never inferred from lockfiles. The composites now also run
  the frozen-lockfile install themselves (`install-dependencies`, default
  `true`) and set up only the selected toolchain (no Bun on npm runs).
- The runners no longer auto-install `vitest`, `@vitest/coverage-v8` /
  `@vitest/coverage-istanbul`, `@playwright/test` or `@lhci/cli`. A missing
  package fails with `install <pkg> as a devDependency and commit the
  <manager> lockfile`. Lighthouse still uses an `lhci` already on `PATH`.
- `reusable-test-e2e.yml` now honours its `package-manager` input (default
  `npm`) instead of always using Bun and gains `bun-version`;
  `reusable-test-e2e-matrix.yml` gains both `package-manager` (default `npm`)
  and `bun-version`.
- `node-version` default is `22` (was `20`) on the three composites,
  `reusable-test-node.yml`, `reusable-test-node-custom.yml`,
  `reusable-test-e2e.yml`, `reusable-test-e2e-matrix.yml` and
  `reusable-test-e2e-playwright.yml`.
- Bun is pinned to an exact version (`bun-version` default `1.4.2`,
  Renovate-managed).
- `run-tests` forwards an optional `package-manager`; its vitest and
  playwright runners fail when it is empty.
- `run-lighthouse` gains `working-directory` (default `.`); `output-dir` and
  `config-path` resolve relative to it.

**Symptom if ignored:** composite: GitHub does not enforce `required:` on
action inputs, so the step runs and the runner's guard fails it with
`package-manager is required for execution actions` (exit 2).
Missing tooling: exit 1 naming the package. Bun project on the e2e reusables:
the job sets up and installs with npm instead of Bun.

**Change:**

```yaml
- uses: lgtm-hq/lgtm-ci/.github/actions/run-vitest@<sha> # v0.76.0
  with:
    package-manager: npm # bun | npm | pnpm, required
    node-version: "20" # optional: keep the pre-v0.76 runtime (default is now 22)
```

*Fragment: permissions omitted for brevity, not copyable as-is. See
[Permissions by mode](../workflow-contract.md#permissions-by-mode).*

```yaml
uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-test-e2e.yml@<sha> # v0.76.0
with:
  package-manager: bun # default is npm; Bun projects must say so
```

```sh
# Add the tooling your config uses, then commit the lockfile
npm install --save-dev vitest @vitest/coverage-v8 @playwright/test @lhci/cli
```

pnpm projects also need `"packageManager": "pnpm@<x.y.z>"` in
`package.json`; `pnpm/action-setup` reads it.

## 3. Egress presets are enforced

Source: #1094 (#913), with preset additions in #1106 and #1119. Contract:
[Egress allowlists](../workflow-contract.md#egress-allowlists).

Before v0.76.0, `egress-preset` and `allowed-endpoints-mode` had **no effect**:
harden-runner installs its agent in its pre hook, before any step runs, and
the allowlist lgtm-ci computed in a later step reached nothing. Each reusable
enforced a hard-coded default list (or the caller's raw `allowed-endpoints`).
From v0.76.0 every harden-runner step composes its allowlist at job start from
a preset map embedded in the workflow, so all three egress inputs take effect.

<!-- markdownlint-disable MD013 -- wide semantics table -->

| Inputs you pass | v0.75.x enforced | v0.76.0 enforces |
| --------------- | ---------------- | ---------------- |
| nothing | the workflow's hard-coded list | the workflow's default preset (same hosts or a superset, except `uploads.github.com:443` on the coordinator jobs listed in 3a) |
| `egress-preset: X` | the hard-coded list (X ignored) | preset X |
| `allowed-endpoints: L`, mode `replace` | L | L (unchanged) |
| `allowed-endpoints: L` + `allowed-endpoints-mode: append` | L (append ignored) | preset + L |
| unknown preset name (block) | job fails at *Checkout and harden*: `unknown egress preset: X` | job fails by name: `::error title=unknown egress-preset::` |

<!-- markdownlint-enable MD013 -->

`allowed-endpoints-mode` defaults to `replace` everywhere except
`reusable-build-rust-binaries.yml`, `reusable-publish-rust-release.yml` and
`reusable-vuln-suppression-check.yml`, which default to `append` (as in
v0.75.x).

### 3a. An explicit `egress-preset` is now what you get

**Who:** callers that pass `egress-preset` or `allowed-endpoints` to any
reusable, under `egress-policy: block` (the default). This now includes jobs
that ignored those inputs in v0.75.x and ran on a fixed inline list: the
`prepare` / `aggregate` jobs of `reusable-test-python.yml` and
`reusable-rust-test.yml`, the `setup` / `merge` jobs of
`reusable-test-e2e-matrix.yml`, and the `rerun` job of
`reusable-auto-rerun-on-infra-failure.yml`. A preset or `replace` list you
tuned for the test legs must also cover what those jobs need (GitHub API and
the artifact service).

**Symptom if ignored:** if the preset is narrower than what the job needs, the
job fails on blocked network calls (connection refused / DNS errors in the
step that downloads). Example: passing `egress-preset: pypi` to
`reusable-security-audit.yml` (default `quality`) now blocks its GHCR login.

**Change:** remove the input to get the workflow's default, or pass a preset
that covers the job. Six defaults changed, so a caller that copied the *old*
default name explicitly now gets a narrower list than the new default:

<!-- markdownlint-disable MD013 -->

| Reusable | Old default | New default | If you pass the old name explicitly |
| -------- | ----------- | ----------- | ----------------------------------- |
| `reusable-auto-rerun-on-infra-failure.yml` | `github-minimal` | `github-results` | blob storage is blocked; the rerun cannot read job results |
| `reusable-build-artifact.yml` | `quality` | `build-artifact` | `nodejs.org:443` is blocked (Node downloads fail) |
| `reusable-build-python-dist.yml` | `pypi` | `python-dist` | Sigstore attestation hosts are blocked |
| `reusable-release-version-pr.yml` | `github-tooling` | `release-version-pr` | the python / pep621 / rust updaters cannot reach PyPI or crates.io |
| `reusable-release-multi-ecosystem.yml` | `github-tooling` | `release-version-pr` | same as above |
| `reusable-test-shell.yml` | `github-tooling` | `shell-test` | apt mirrors (kcov dependencies) are blocked |

<!-- markdownlint-enable MD013 -->

```yaml
# Before (decorative in v0.75.x, enforced and too narrow in v0.76.0)
with:
  egress-preset: github-minimal
# After: drop the line, or name the new default
with:
  egress-preset: github-results
```

Valid preset names: `github-minimal`, `github-results`, `github-tooling`,
`github-pages`, `docker`, `playwright`, `pypi`, `python-dist`, `rubygems`,
`npm-publish`, `quality`, `build-artifact`, `shell-test`, `sbom`, `scorecard`,
`osv-scanner`, `ai-review`, `rust-release`, `release-recover`,
`release-version-pr`, `external-canary` (GitHub API only; used by lgtm-ci's
own canary, #1124). The hosts behind each are in
`scripts/ci/lib/egress/presets.sh`.

### 3b. `allowed-endpoints-mode: append` widens instead of replacing

**Who:** callers passing `allowed-endpoints` together with
`allowed-endpoints-mode: append`, and callers passing only `allowed-endpoints`
to the three reusables whose mode defaults to `append` (see above).

**Symptom if ignored:** none that fails; the job now allows the preset *plus*
your list, where before only your list applied. If your list was a complete
allowlist, set `allowed-endpoints-mode: replace` explicitly to keep the job at
exactly that list. Dropping the input only restores `replace` where that is the
default; on the three append-default reusables it leaves you on `append`.

### 3c. Unknown preset names fail by name

Unknown names already failed in v0.75.x under `block` (inside *Checkout and
harden*). Now a `Fail on unknown egress-preset` step follows every
caller-selectable harden-runner step and names the problem. It is skipped
under `egress-policy: audit` and when a non-empty `allowed-endpoints` replaces
the preset. Fix the typo or pick a name from the list above.

### 3d. Removed egress inputs and actions

**Who:** direct users of the `checkout-and-harden` composite, and anyone
referencing the removed composites.

- `checkout-and-harden` no longer accepts `egress-policy`, `egress-preset`,
  `allowed-endpoints` or `allowed-endpoints-mode`, and no longer outputs
  `allowed-endpoints`. Passing them only produces an `Unexpected input(s)`
  warning, and the removed output reads as empty, so nothing fails loudly:
  delete those `with:` keys and any use of the output. To harden your own
  job, run `step-security/harden-runner` directly as its first step.
- The `.github/actions/resolve-egress-allowlist` composite is deleted (a
  `uses:` pointing at it fails to resolve), as are the
  `.github/actions/harden-runner` script bundle, `scripts/ci/lib/egress.sh`
  and `scripts/ci/actions/resolve-egress-endpoints.sh`.
- `reusable-release-recover.yml`, `reusable-sbom-release-upload.yml` and
  `reusable-scorecards.yml` gain `egress-preset` and `allowed-endpoints-mode`.
- Every `allowed-endpoints` input now defaults to `""`; the preset is the
  baseline. On `reusable-deploy-site-with-reports.yml` the same applies to
  `allowed-endpoints-build` / `allowed-endpoints-deploy`, with
  `egress-build-preset` (`playwright`) and `egress-deploy-preset`
  (`github-pages`) as baselines.

### 3e. Preset changes that may let you delete overrides

- `release-version-pr` (new, #1106) includes PyPI and crates.io hosts. Callers
  that pasted `pypi.org:443 files.pythonhosted.org:443` into
  `allowed-endpoints` for the python / pep621 bump can drop them.
- `rust-release` (#1119) gains `aka.ms:443` and
  `download.visualstudio.microsoft.com:443` for the new cargo-xwin Windows
  build ([section 9](#9-smaller-behaviour-changes)). If you call
  `reusable-build-rust-binaries.yml` with your own `allowed-endpoints` and an
  explicit `allowed-endpoints-mode: replace` (its default is `append`) and
  build `x86_64-pc-windows-msvc`, add both hosts.

### Known gap: Playwright on GitHub-hosted runners (#1103)

The `playwright` preset does not list `azure.archive.ubuntu.com:80` or
`storage.googleapis.com:443`, so `playwright install --with-deps` can be
refused under `block` on GitHub-hosted runners. v0.75.x's hard-coded lists
had the same gap. Until #1103 ships, append them:

```yaml
with:
  allowed-endpoints: azure.archive.ubuntu.com:80 storage.googleapis.com:443
  allowed-endpoints-mode: append
```

## 4. `version-update-script` runs in its own unprivileged job

Source: #1097 (#849). Reference:
[Version update hook](../reusable-workflows.md#version-update-hook-version-update-script).

**Who:** callers of `reusable-release-version-pr.yml` or
`reusable-release-multi-ecosystem.yml` that pass `version-update-script`.
Without a hook the two new jobs are skipped; the token scoping below still
applies to every caller.

**What changed:**

- The hook runs in a new job, `version-update-hook` ("Run version update
  hook"), with `permissions: contents: read`, **no secrets and no token of any
  kind**. A new `prepare` job ("Prepare version update hook") computes the
  version and writes `release-metadata.json`. The App token is minted only in
  `prepare` and `version-pr`, which run lgtm-ci code only.
- The hook receives `NEXT_VERSION` and `RELEASE_METADATA_PATH` (read-only
  JSON: `latest_release` tag/version/date/URL, and with
  `release-metadata-container-package` set, `container` =
  `{package, version, digest}` for the newest release-tagged image;
  `latest_release` and `container` are each `null` when unavailable).
  Setting `release-metadata-container-package` makes `prepare` request
  `Packages: read` on the App token.
- The tooling checkout (`.lgtm-ci-tooling/`) is read-only during the hook.
- The hook's edits to repository files (tracked changes and new, not
  gitignored files) travel to `version-pr` as a `git diff`. Writes outside
  the repository or to gitignored paths are not carried over. The diff is
  rejected if it touches `.github/**` (matched case-insensitively), the
  tooling checkout or `.git/`, adds a symlink or submodule, or was built for a
  different version.
- Every App token minted by the release reusables
  (`reusable-release-version-pr.yml`, `reusable-release-multi-ecosystem.yml`,
  `reusable-release-auto-tag.yml`) is scoped to the calling repository
  (`repositories: ${{ github.event.repository.name }}`).

**Symptom if ignored:** a hook that writes into `.lgtm-ci-tooling/`, edits
anything under `.github/`, adds a symlink or submodule, or exits non-zero
fails the `version-update-hook` job before any branch, commit or PR is
created. Edits outside the repository or to gitignored files silently do not
reach the PR. The hook never had a token (v0.75.x did not pass one either),
and the job now fails if one is present in its environment.

**Change:** read API data from the metadata file, and keep edits to
repository files outside `.github/`.

```sh
#!/usr/bin/env bash
# scripts/release/finalize.sh — called as version-update-script
set -euo pipefail
latest_tag=$(jq -r '.latest_release.tag // empty' "$RELEASE_METADATA_PATH")
digest=$(jq -r '.container.digest // empty' "$RELEASE_METADATA_PATH")
sed -i "s/^version = .*/version = \"${NEXT_VERSION}\"/" packaging/manifest.toml
```

*Fragment: permissions omitted for brevity, not copyable as-is. See
[Permissions by mode](../workflow-contract.md#permissions-by-mode).*

```yaml
uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-release-version-pr.yml@<sha> # v0.76.0
with:
  version-update-script: scripts/release/finalize.sh
  release-metadata-container-package: my-image # optional; App needs Packages: read
```

A future cross-repository write (for example a Homebrew tap) will take the
target repository as an explicit input; the default token cannot reach a
second repository.

### Known issue: gitignored tooling checkout

> [!WARNING]
> In v0.76.0, if a `.gitignore` pattern in your repository matches the
> `.lgtm-ci-tooling` **directory itself** (for example `.lgtm-ci-tooling`,
> `.lgtm-ci-tooling/`, `/.lgtm-ci-tooling/` or `.lgtm-*`), the
> `version-update-hook` job fails in its `Run repo-specific version update
> script` step, before your script runs, with `The following paths are ignored
> by one of your .gitignore files: .lgtm-ci-tooling`. The hook script
> snapshots the workspace with `git add -A -- . ":(exclude).lgtm-ci-tooling"`,
> and git exits 1 when an exclude pathspec names an ignored path.
>
> Workaround: replace the pattern with `.lgtm-ci-tooling/*`, which keeps the
> contents ignored and does not trigger the error, or remove it. Either is
> safe: the hook job excludes the tooling checkout from its diff and the scope
> check rejects it, and `version-pr` deletes the tooling checkout before
> `create-pull-request` stages anything, so it never reaches the PR. Callers
> without `version-update-script` are not affected.

## 5. Drop `tooling-ref`

Source: #1084 (#995), already in v0.75.3; v0.76.0's examples no longer pass it
(#1114).

**Who:** callers that still pass `tooling-ref` to any reusable other than
`reusable-release-recover.yml`.

**What changed:** reusables resolve their own tooling from `job.workflow_sha`
/ `job.workflow_repository`. A set `tooling-ref` is an override that emits
`::warning title=tooling-ref override::tooling-ref is no longer required;
remove it to track the workflow pin automatically`, plus the mismatch when it
differs from the pin.

**Symptom if ignored:** the warning on every run. Worse, if you bump the
`uses:` pin to v0.76.0 and leave `tooling-ref` at a v0.75.x SHA, v0.76.0
workflows run v0.75.x scripts (for example without
`wait-for-artifacts.sh`, `configure-git-deps-auth.sh` or
`run-version-update-hook.sh`) and fail in ways that do not point at the stale
ref.

**Change:**

```yaml
with:
  tooling-ref: 31750ecad528ca9312bfe169dd33325b18f6c637 # delete this line
```

Keep it on `reusable-release-recover.yml`, where it is deliberately required
and must equal the `uses:` SHA, and on direct `prepare-pypi-upload` steps.

## 6. `artifact-prefix` and renamed artifacts

Source: #1108 (#1091). Reference:
[Calling a language test reusable twice in one run](../reusable-workflows.md#calling-a-language-test-reusable-twice-in-one-run-1091).

**Who:**

- Callers that invoke one of `reusable-test-python.yml`,
  `reusable-test-node.yml`, `reusable-test-node-custom.yml`,
  `reusable-rust-test.yml` or `reusable-test-shell.yml` more than once in the
  same workflow run.
- Anything that downloads `node-custom-coverage` by name.
- Callers that pass `coverage-artifact-name: ""` to the Node reusables to
  suppress the coverage comment.

**What changed:** each of those reusables, plus
`reusable-test-python-publish.yml` and `reusable-test-node-publish.yml`, takes
`artifact-prefix` (`[A-Za-z0-9_.]+`). Defaults are the language words
(`python`, `node`, `node_custom`, `rust`, `shell`), so single-call callers
keep their artifact names. Every upload, download glob and summary handoff is
built from it.

- `reusable-test-node-custom.yml`'s default coverage artifact is now
  `node_custom-coverage` (was `node-custom-coverage`; `-` is the reserved
  separator).
- `coverage-artifact-name` on the Node reusables defaults to `""`, which
  resolves to `<artifact-prefix>-coverage`. An explicit empty value no longer
  suppresses the coverage comment; use `coverage: false`.
- `pages-coverage-artifact-name` is not derived from the prefix (default stays
  `coverage-html`).

**Symptom if ignored:** with two calls and no prefix, the second call's
`<lang>-coverage` (and `<lang>-results-<version>` when versions match)
silently replaces the first while the run stays green.

**Change:**

```yaml
jobs:
  test-core:
    permissions:
      actions: read
      contents: read
      pull-requests: write
    uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-test-python.yml@<sha> # v0.76.0
    with:
      working-directory: core
      artifact-prefix: core
  test-plugins:
    permissions:
      actions: read
      contents: read
      pull-requests: write
    uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-test-python.yml@<sha> # v0.76.0
    with:
      working-directory: plugins
      artifact-prefix: plugins
```

When you also call a `*-publish` reusable for a prefixed test call, pass it the
same `artifact-prefix`.

## 7. Python installs use `uv sync --frozen`

Source: #1112 (#1021). Contract:
[Frozen installs and private git dependencies](../workflow-contract.md#frozen-installs-and-private-git-dependencies-1021).

**Who:** callers of `reusable-test-python.yml` (and the `setup-python` /
`run-pytest` paths) whose `uv.lock` is out of date with `pyproject.toml`, or
whose installed dependency groups contain private git dependencies.

**What changed:** dependency install is `uv sync --frozen` and every
project-scoped `uv run` is `uv run --frozen`: the committed lock is installed
verbatim and only installed groups are fetched. A project with
`pyproject.toml` but no `uv.lock` (in the directory or any ancestor) gets one
warned `uv lock` first. New optional secret `GIT_DEPS_TOKEN` with inputs
`git-deps-host` (default `github.com`) and `git-deps-username` (default
`x-access-token`) configure host-scoped git auth around the install.

**Symptom if ignored:** a stale lock is no longer silently re-resolved in CI;
tests run against the locked versions, which may differ from what
`pyproject.toml` now asks for.

**Change:** run `uv lock`, commit `uv.lock`, and add `uv lock --check` to your
own CI. For private git dependencies in installed groups:

```yaml
jobs:
  test:
    permissions:
      actions: read
      contents: read
      pull-requests: write
    uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-test-python.yml@<sha> # v0.76.0
    with:
      git-deps-host: github.com
    secrets:
      GIT_DEPS_TOKEN: ${{ secrets.PRIVATE_DEPS_TOKEN }}
```

The private host must also be reachable under your egress allowlist.

## 8. Tool version overrides need a digest

Source: #1113 (#1096), extended to cargo-xwin in #1119. Contract:
[Supplier tool pins and digests](../workflow-contract.md#supplier-tool-pins-and-digests).

**Who:** callers that override a supplier tool version lgtm-ci installs:
`bats-version` on `reusable-test-shell.yml`, `osv-version` on
`reusable-vuln-suppression-check.yml`, or `CARGO_NEXTEST_VERSION` /
`CARGO_LLVM_COV_VERSION` through a Rust `setup-script`.

**What changed:** every tool has one pin in `scripts/ci/versions.env`, and
every download or clone is checked against a committed sha256 or commit. A
mismatch always fails. A version override without its matching digest is an
error unless the caller opts into `LGTM_CI_ALLOW_UNVERIFIED=1`. `lintro-version`
on `reusable-ai-review.yml` now defaults to `""` (resolved from
`versions.env`); passing a version still works.

**Symptom if ignored:** `::error title=unverified install::… Set
LGTM_CI_ALLOW_UNVERIFIED=1 to continue unverified.`

**Change:** drop the override to use lgtm-ci's pin, or pair it with its digest:

```yaml
with:
  bats-version: "1.11.1"
  bats-commit: <40-hex commit of the v1.11.1 tag> # new companion input
```

`reusable-test-shell.yml` has no script hook, so a `bats-version` override
always needs `bats-commit`.

Caller `env:` does not cross the `workflow_call` boundary, and no lgtm-ci
workflow sets or forwards `LGTM_CI_ALLOW_UNVERIFIED`. The only route for the
other overrides is a caller script that **replaces** lgtm-ci's installer:
`install-script` on `reusable-vuln-suppression-check.yml` (run as
`bash "$GITHUB_WORKSPACE/$INSTALL_SCRIPT" "$OSV_VERSION"`) and
`setup-script` on `reusable-rust-test.yml` (default
`.lgtm-ci-tooling/scripts/ci/testing/rust/setup-rust-nextest.sh`). Export the
digest (or, accepting the risk, `LGTM_CI_ALLOW_UNVERIFIED=1`) and hand off to
lgtm-ci's installer:

```sh
#!/usr/bin/env bash
# ci/install-osv.sh — passed as install-script
set -euo pipefail
export OSV_SCANNER_SHA256_LINUX_AMD64=<sha256 of the release asset>
exec bash .lgtm-ci-tooling/scripts/ci/security/install-osv-scanner.sh "$@"
```

For nextest / llvm-cov, do the same with `CARGO_<TOOL>_SHA256_<TARGET>` and
`exec bash .lgtm-ci-tooling/scripts/ci/testing/rust/setup-rust-nextest.sh`.

## 9. Smaller behaviour changes

Each of these turns a silent failure into a loud one or changes a default.
Review the ones that match your setup.

- **Results contract (#1125).** The python, node, rust, shell,
  e2e-playwright, coverage and security-audit reusables (and the
  `run-pytest` / `run-vitest` / `run-playwright` composites) now write one
  `results.json` per leg ([results.v1](../workflow-contract.md#results-contract-schemasresultsv1json-1080)),
  and the PR comment and step summaries read only those.
  `reusable-required-check.yml` checks them only when you pass
  `results-artifact-pattern`. `reusable-test-node-custom.yml`,
  `reusable-test-e2e.yml` and `reusable-test-e2e-matrix.yml` are unchanged.
  Workflow outputs keep their names and values, with one exception: the
  `tests-passed` output of `reusable-test-shell.yml` (and the shell comment's
  Passed row and pass rate) no longer counts bats `# skip` tests, which now
  appear under Skipped; `tests-total` is unchanged. What else a caller can
  notice:
  - A leg whose pytest / vitest / Playwright report is missing or not valid
    JSON is now `status: error` and fails the aggregate, where v0.75.x
    reported 0 tests and stayed green on exit 0. The summary job fails when
    the expected number of `results.json` legs is missing, instead of posting
    an empty comment.
  - `<prefix>-results-<version>` artifacts carry `results.json` instead of the
    untyped `summary.json`. Anything of yours that downloads them and reads
    `summary.json` must read `results.json` (`counts.passed` /
    `counts.failed` / `counts.skipped` / `counts.total`, `status`,
    `duration_ms`).
  - New artifacts, additive: `<prefix>-results` (`reusable-test-shell.yml`),
    `<report-artifact-name>-results`, or `playwright-results-<run_id>` when
    `report-artifact-name` is empty (`reusable-test-e2e-playwright.yml`; input
    `results-artifact-name` overrides both), `security-audit-results`
    (`reusable-security-audit.yml`, input `results-artifact-name`) and
    `<coverage-artifact-name>-results` (`reusable-coverage.yml`). Re-check any
    broad download pattern of your own.
  - The PR comment's **Skipped** row shows the real count (it was always
    `0`).
  - `reusable-publish-test-summary.yml` and `reusable-required-check.yml`
    gain optional `results-artifact-pattern` / `results-expected-count`
    (and `tests-total-excludes-skipped` on the publisher). The legacy count
    inputs still work for direct callers.
  - Direct composite users: the parse step now also writes
    `results/<tool>/<leg>/results.json` into the working directory; exclude
    `results/` if you upload or commit the workspace.
- **Security audit comment (#1109).** `format-security-comment.py` reads
  `metadata.suppressions` (py-lintro ≥ 0.95.0) instead of the removed
  `ai_metadata` key, with a warned fallback. If `.osv-scanner.toml` has dated
  entries but the lintro probe produced no suppression data (probe disabled
  with `check_suppressions: false`, or timed out), the audit now reports
  `FORMAT FAILED` instead of a static table. Fix: re-enable the probe, or
  remove stale dated entries. Repos with their own copy of the script must
  switch keys themselves.
- **Playwright reports (#1104).** `reusable-test-e2e-playwright.yml` passes
  one combined `--reporter` flag and **fails when `playwright-report/` is
  missing**, even if every test passed. New inputs there: `reporters`
  (default `list,json,junit,html`; must keep `json` and `html`) and
  `upload-report-when` (`failure` default, or `always`). A `test-command`
  that passes its own `--reporter` gets a warning; the `reporters` input
  wins. `playwright-results.xml` joins the report artifact. The
  `run-playwright` composite keeps its `reporter` input; with
  `reporter: html` it now fails when `playwright-report/` is missing, and it
  warns when `extra-args` contains `--reporter`.
- **Coverage format (#1101).** The `collect-coverage` composite's
  `output-format` default is `""` (keep the input format), was `json`. Direct
  users that relied on JSON output from JSON/istanbul input pass
  `output-format: json`. Unsupported conversions fail with
  `::error::unsupported coverage conversion: <src> -> <dst>`, and content is
  validated against the detected format. `reusable-coverage.yml` gains the
  same `output-format` input; LCOV callers that failed with `cannot convert
  from lcov to json` now work with no change. Line-only LCOV reports branch
  and function totals as `n/a`. `collect-coverage` gains a `merged-format`
  output.
- **Rust Windows builds (#1119).** `build-rust-binary.sh` rejects `cross` with
  any `*-msvc` target (exit 2). The default release matrix builds
  `x86_64-pc-windows-msvc` with `{"builder":"xwin"}`. If you pass your own
  matrix containing `{"target":"x86_64-pc-windows-msvc","cross":true}`, change
  it to `"builder":"xwin"` (or use `x86_64-pc-windows-gnu` with cross). That
  combination never compiled; it now fails earlier with a clear message.
- **Rust concurrency (#1119).** `reusable-test-rust-build.yml`,
  `reusable-rust-test.yml` and `reusable-build-rust-binaries.yml` key their
  concurrency group on the caller repository, `github.workflow` and the ref,
  so two caller workflows on one ref no longer cancel (or, for
  `reusable-build-rust-binaries.yml`, which keeps `cancel-in-progress: false`,
  queue behind) each other. New optional `concurrency-scope` input (also on
  `reusable-rust-build.yml`) to separate calls within one workflow.
- **nextest JUnit path (#1106).** If you copied `examples/nextest-ci.toml`,
  set `junit.path = "junit.xml"` (nextest resolves it relative to
  `target/nextest/ci/`). The old value wrote the report to a nested path and
  `parse-rust-test-results.sh` failed after a green run.
- **Composite actions used directly (#1089, #1102).** `run-pytest` references
  `setup-python` with the `$/` self-repository form, so it works without an
  lgtm-ci checkout in your workspace; self-hosted runners must be ≥ 2.336.0,
  and on GHES use `reusable-test-python.yml` instead. `run-vitest`,
  `run-playwright` and `run-lighthouse` set up their toolchain directly
  ([section 2](#2-node-runners-package-manager-devdependencies-node-22)).
- **Python dist on shallow checkouts (#1107).** The `build-python-package`
  composite's tag-on-default-branch preflight fetches the default branch when
  it is missing. In a private repository, a shallow checkout with
  `persist-credentials: false` cannot fetch and fails naming the fix:
  `fetch-depth: 0` or `persist-credentials: true` (public repositories fetch
  anonymously). An invalid `default-branch` value is now rejected.
- **AI review (#1099).** A review that hits its time bound (what remains of
  `timeout-minutes` after preflight, minus a 240 s margin) is a `timed-out`
  outcome with a PR comment instead of a cancelled job; it is neutral unless
  `blocking: true`. New optional `max-diff-lines` input (default `0`, off)
  skips oversized diffs with a PR comment.
- **`reusable-test-node.yml` (#1102)** gains an optional `post-test-command`.
- **`sign-artifact` composite (#1100)** gains an optional `repository` input
  (default `${{ github.repository }}`) for the release-upload step.

## 10. Fixes that need no caller change

- `reusable-sbom-release-upload.yml` sets `GH_REPO` on the upload step; it
  failed on every tag run with `not a git repository` (#1100).
- `reusable-release-version-pr.yml` creates `CHANGELOG.md` with a Keep a
  Changelog header when it is missing, instead of failing (#1106).
- The matrix aggregate retries only artifact-listing under-counts and 404s on
  listed artifacts; over-counts and foreign names still fail at once (#1105).
- New support-tier catalog, [docs/catalog.md](../catalog.md) (#1126): every
  public workflow and action is `stable`, `preview`, `internal` or
  `deprecated`, with its caller permissions, prerequisites and the fixture
  run behind a `stable` rating. `reusable-publish-npm.yml` is recorded as
  `deprecated` (since #965, unchanged) in favour of
  `reusable-publish-npm-set.yml`.
- An external-consumer canary (#1124) now runs the
  [consumer fixture](https://github.com/TurboCoder13/lgtm-ci-consumer-fixture)
  against a candidate lgtm-ci commit, so a release is proven from a real
  caller repository before it is tagged. It adds no caller inputs.
- Tool pins bumped: uv 0.12.23, nextest 0.9.146, syft 1.54.1, grype 0.120.1,
  cargo-binstall 1.25.2 (#1069, #1070, #1115–#1117).
