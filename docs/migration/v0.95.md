# Upgrading to v0.95.0: private mirrors pass `LGTM_CI_TOOLING_TOKEN`

Applies to every reusable workflow that checks out the lgtm-ci tooling, which
is every one except `reusable-scorecards.yml` (#1451). Nothing in this release
is breaking. A caller that does not use a private mirror has nothing to do.

## What it does

Each reusable checks out its own tooling into `.lgtm-ci-tooling`. When the
tooling repository is a private mirror, the job's `github.token` cannot read
it and that checkout fails. The reusables now take an optional secret,
`LGTM_CI_TOOLING_TOKEN`, declared with `required: false`:

- **Which jobs use it.** Only the tooling checkout steps, in every job that
  checks out the tooling, and the `tooling-token` input of
  `checkout-and-harden`, which hands it to the composite's own tooling
  checkout. No other step reads it. Every such checkout uses
  `token: ${{ secrets.LGTM_CI_TOOLING_TOKEN || github.token }}` with
  `persist-credentials: false`. The `version-update-hook` job of the two
  release reusables never receives it (see below).
- **Scope.** A token with contents read on the tooling repository only: no
  other permission, no other repository, the shortest expiry you can operate.
  Store it as a repository or organisation secret. It cannot be minted in an
  earlier job of the same run, because the runner drops a job output that
  holds a secret.
- **It does not isolate anything.** The caller's own code runs later in the
  same job and can read the tooling, and with effort the token. Pass it only
  from trusted callers on trusted runners.
- **Passing it.** Pass it by name to each reusable you call:

  ```yaml
  jobs:
    semantic-title:
      uses: <owner>/<mirror>/.github/workflows/reusable-semantic-pr-title.yml@<sha>
      secrets:
        LGTM_CI_TOOLING_TOKEN: ${{ secrets.LGTM_CI_TOOLING_TOKEN }}
  ```

  A wrapper reusable of your own declares the secret under
  `on.workflow_call.secrets` with `required: false` and forwards it the same
  way, by name, to each lgtm-ci reusable it calls. Do not use
  `secrets: inherit`: it hands over every secret. Passing the secret to a
  reusable that does not declare it is a workflow error.

- **Fork pull requests** receive no secrets. The checkout falls back to
  `github.token`, which works for a public tooling repository and fails
  against a private mirror, as before.

The full contract, and what the repository's own validator enforces, is in
[Tooling token](../workflow-contract.md#tooling-token-1451).

## Behaviour changes you could notice

These apply whether or not you pass the secret.

- **The release reusables' tooling checkouts no longer use the release App
  token.** In `reusable-release-auto-tag.yml`,
  `reusable-release-version-pr.yml` and
  `reusable-release-multi-ecosystem.yml`, the tooling checkouts that used the
  App installation token now use `LGTM_CI_TOOLING_TOKEN` or `github.token`.
  The installation token is scoped to the caller repository, so it could not
  read a separate mirror before either. Release writes still use the App
  token.
- **The `version-update-hook` job no longer checks out the tooling.** In
  `reusable-release-version-pr.yml` and
  `reusable-release-multi-ecosystem.yml`, the `prepare` job packs
  `scripts/ci` from its own tooling checkout into a tarball, uploads it as the
  artifact `release-version-pr-tooling-<key>` or
  `release-multi-ecosystem-tooling-<key>` (kept for one day), and passes its
  SHA-256 as the `tooling-digest` job output. The hook job downloads it,
  checks the digest and extracts it into `.lgtm-ci-tooling` before any step
  reads or runs your code. The hook job still holds no secret and no token.
- **The hook job no longer runs the tooling-ref divergence guard itself.**
  `prepare` already ran it on the tree it now packs, so a `tooling-ref`
  override that diverges from the workflow commit still stops the run, in
  `prepare`, before the hook job starts. The hook job's log no longer shows
  the guard step.
- **A caller repository that contains a `.lgtm-ci-tooling` directory now
  fails the hook job.** The extract step creates that directory and fails if
  your checkout already has it. Remove or rename the directory in your
  repository.
