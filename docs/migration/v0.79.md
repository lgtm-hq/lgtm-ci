# AI review auth selection (next feature release)

Review auth resolves `auth` input → `LINTRO_AI_AUTH` variable → static tuple
default. Anthropic CLI and OpenAI CLI default to subscription OAuth. **OpenAI CLI
changes from the previous API-key default deliberately**: CI reviews use the CLI
subscription; generic API source secrets are smoke-only. Explicit `auth: api_key`
remains supported with dedicated review sources. No secret-presence fallback exists.

Keep the generic reusable slots and use the complete explicit caller block in
[reusable workflows](../reusable-workflows.md#ai-code-review-reusable-ai-reviewyml).
OpenAI CLI OAuth needs base64 `CODEX_AUTH_JSON`; `CODEX_API_KEY` must be absent from
the OAuth invocation environment. API callers map `ANTHROPIC_REVIEW_API_KEY` and
`OPENAI_REVIEW_API_KEY` to the corresponding generic slots. `secrets: inherit`
supports OAuth-only callers, never the API-key remapping contract.

Under block egress, both provider and transport must be visible as workflow inputs
or Actions variables at harden-runner job start. Auth is visible there from the
input, variable or static default. Config-only tuple components cannot widen the
allowlist after checkout. OAuth OpenAI CLI uses `chatgpt.com` / `auth.openai.com`;
API-key OpenAI modes use `api.openai.com`. The capability matrix generates these
bindings; run `uv run python scripts/ci/workflows/sync_ai_review_matrix.py --check`.

Review invocation now isolates all repo/runner CLI config, dotenv, hooks, helpers,
PATH additions and cached logins. Only resolved provider/transport, model and
cost-cap scalars cross from reviewed config. Custom agents and arbitrary repo
settings do not enter credential scope. Minimum lintro is 0.173.1. Renew session
snapshots through the authoritative secret source; refreshed disposable copies are
not written back.

Known consumers retain their existing pins until separately reviewed adoption.
`check-deprecations.sh scan --write` records source-expression findings and reports
unresolved variable/config auth as unverified; it cannot verify encrypted secret
availability or a live review. Provisioning credentials is an operator task.
Podex adoption must update both workflow/tooling pins and prove a completed posted
review after release. No release, external consumer edit, global routing change or
secret provisioning is part of this implementation PR.
