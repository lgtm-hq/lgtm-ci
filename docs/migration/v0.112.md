# Upgrading to v0.112.0: egress presets drop hosts no current client reaches

Applies to callers that run Playwright 1.49 or older through the `playwright`
egress preset (#1644). Nobody else has anything to do.

## What changed

Three hosts on domains where anyone can register a name were in the presets
without current evidence that any client reaches them. They are removed:

| Host                                           | Presets                               | Why it is gone                                                                                                                                                 |
| ---------------------------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `playwright.azureedge.net:443`                 | `playwright`                          | Browser download mirror of Playwright 1.49 and older. Since 1.50 Playwright downloads from `cdn.playwright.dev`, which stays.                                  |
| `playwright-akamai.azureedge.net:443`          | `playwright`                          | Same.                                                                                                                                                          |
| `sigstore-tuf-root.storage.googleapis.com:443` | `python-dist`, `sbom`, `rust-release` | Legacy location of Sigstore's TUF root. cosign, `gh attestation`, `actions/attest*` and sigstore-js all read it from `tuf-repo-cdn.sigstore.dev`, which stays. |

The reusables that use these presets are `reusable-test-e2e.yml`,
`reusable-test-e2e-matrix.yml`, `reusable-test-e2e-playwright.yml`,
`reusable-deploy-site-with-reports.yml` (build job, `playwright`),
`reusable-build-python-dist.yml`, `reusable-sbom.yml` and
`reusable-build-rust-binaries.yml`.

Two hosts stay, now with their evidence beside them in
`scripts/ci/lib/egress/presets.sh`:
`docker-images-prod.s3.dualstack.us-east-1.amazonaws.com` (Docker Hub layer
redirects) and `tmaproduction.blob.core.windows.net` (GitHub's attestation
store, now checked daily by `results-hosts-drift.yml`).

The Homebrew re-dispatch and record jobs of the internal
`reusable-release-recover-resume.yml` now run under `github-minimal` instead
of `release-recover`. They talk to the GitHub API only, so nothing changes for
callers of `reusable-release-recover.yml`.

## Are you affected?

Only if your project's `@playwright/test` is 1.49 or older. That is possible
only on `runner-image: ubuntu-24.04` (or a self-hosted runner), because the
default `ubuntu-26.04` runner already requires 1.61 or newer. The
`playwright install` step then fails: harden-runner blocks the connection to
`playwright.azureedge.net`, and the job's harden-runner insights list it as
blocked.

## What to do

Upgrade `@playwright/test` to 1.50 or newer (1.61 or newer for the default
runner). If you cannot yet, add the old mirrors yourself:

```yaml
with:
  allowed-endpoints-mode: append
  allowed-endpoints: >-
    playwright.azureedge.net:443
    playwright-akamai.azureedge.net:443
```

A step of your own that still runs a Sigstore client configured with the
legacy GCS mirror should switch it to `https://tuf-repo-cdn.sigstore.dev`,
the default of every current client.
