# Upgrading to v0.97.0: `reusable-publish-npm.yml` is removed

Applies to callers of `reusable-publish-npm.yml` (#1526). The single-package
wrapper was deprecated in v0.72.0 (#965) and is now deleted. A pin to this
release or later that still calls it fails with a `startup_failure`, because the
file no longer exists. No other caller has anything to do.

## Migrating from `reusable-publish-npm.yml`

Call `reusable-publish-npm-set.yml` directly. A single package is a set of
one: the package directory is `packages-dir` and `order` is `"."`, which is
exactly what the wrapper forwarded.

```yaml
jobs:
  npm:
    uses: lgtm-hq/lgtm-ci/.github/workflows/reusable-publish-npm-set.yml@<sha> # vX.Y.Z
    permissions:
      contents: read
      id-token: write
      attestations: write
    with:
      packages-dir: . # was working-directory (default ".")
      order: "." # single-directory shape: the package IS packages-dir
      dry-run: false # the set defaults to true; the wrapper defaulted to false
      job-name: Publish to npm # optional; check names change anyway, see below
      timeout-minutes: 15 # optional: the wrapper's default (the set's is 30)
      # Required for a live publish, as they already were through the wrapper:
      entry-workflows: .github/workflows/publish-npm.yml
      checksums-file: SHA256SUMS
      signer-repo: <owner>/<repo>
      signer-workflow: .github/workflows/build.yml
```

### Inputs

| Wrapper input                                              | Set input                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------------ |
| `working-directory` (default `.`)                          | `packages-dir` (required), plus `order: "."` (required)      |
| `dry-run` (default `false`)                                | `dry-run` (default **`true`**): pass `false` to publish      |
| `job-name` (default `Publish to npm (deprecated wrapper)`) | `job-name` (default `Publish npm package set`)               |
| `timeout-minutes` (default `15`)                           | `timeout-minutes` (default `30`, room for the registry wait) |

Every other wrapper input has the same name and default on the set and was
forwarded unchanged: `node-version`, `dist-tag`, `provenance`, `access`,
`entry-workflows`, `checksums-file`, `files-to-verify`, `signer-repo`,
`signer-workflow`, `runner-image`, `tooling-ref`,
`tooling-ref-allow-divergence`, `egress-policy`, `allowed-endpoints`,
`allowed-endpoints-mode`, `egress-preset` and `environment`.

The set also takes `artifact-name`, `max-attempts`, `post-publish-verify`,
`propagation-attempts`, `propagation-delay` and `smoke-command`. The wrapper
never passed them, so leaving them out keeps its behaviour.

### Secrets

Drop `npm-token`: the wrapper already refused it, and publishing runs under
npm trusted publishing (OIDC) only. `LGTM_CI_TOOLING_TOKEN` is passed the same
way as before.

### Outputs

| Wrapper output   | With the set                                                               |
| ---------------- | -------------------------------------------------------------------------- |
| `published-set`  | `published` (the same JSON array)                                          |
| `published`      | `fromJSON(needs.npm.outputs.published \|\| '[]')[0].status == 'published'` |
| `version`        | `fromJSON(needs.npm.outputs.published \|\| '[]')[0].version`               |
| `package-name`   | `fromJSON(needs.npm.outputs.published \|\| '[]')[0].name`                  |
| `tarball`        | Removed; it was always empty                                               |
| `dist-tag-drift` | `dist-tag-drift` (unchanged)                                               |

Read `published` with `fromJSON(... || '[]')`: it is a JSON array, not the
wrapper's `'true'`/`'false'` string, so `needs.npm.outputs.published ==
'true'` is never true. The `|| '[]'` guard, which the wrapper used too,
keeps the expression valid when the publish job was skipped.

### Check names

The wrapper's `Deprecation notice` job is gone, and the publish check loses
a level. Through the wrapper it was nested as
`<caller job> / <job-name> / <job-name>`; calling the set directly it is
`<caller job> / <job-name>`. Passing the same `job-name` does not keep the
old name, so update any branch protection or ruleset that requires the old
checks.

### npm trusted publisher

Nothing changes: npm validates the caller's entry workflow file, not the
reusable, so the existing trusted-publisher registration keeps matching.
